Read CLAUDE.md and AGENTS.md first and follow them exactly (requirement IDs, decision records, open-items register, commit-author rule, test-first, checks before push incl. cargo-semver-checks if installed, long-running test rule, coverage rule, draft PR and push once per decision 0055). Commit subjects and PR title start "Lane <NAME>:". Plain wording per decision 0114 / lane X7b. Verify every decision, OI and schema number against main and unmerged branches before using it; ask the coordinator before claiming a project schema number. Git identity: author AND committer Paul Hampson (<id>+<login> users.noreply address, from `git config`), Co-Authored-By for the agent; set git config BEFORE any git merge and check `git log -1 --format='%an <%ae> | %cn <%ce>'` (a default agent identity fails the CLA check and costs a 40-minute CI restart). Library family: a breaking change bumps the workspace minor with a changelog entry (decision 0048); check main for the current version.
Process rules from the owner: (1) Do not merge or mark the PR ready; a merge agent takes over only when your work is complete AND your decision records are accepted; only the owner accepts a record, directly in your session. (2) Do NOT ask the owner directly: send each owner decision to the coordinator session session_01CFw3bzew7zizFQ91L5tvT7 with send_message, ONE decision per message, with question, options, your recommendation and the OI/record number, and wait. (3) Message the coordinator when the PR is complete, naming any record awaiting acceptance. (4) Safety pushes of work in progress to your own branch (no PR) are allowed. (5) "Closes #..." only for what is fully done, otherwise "Refs" (the owner closes issues after testing). (6) Do not edit docs/requirements.md or docs/architecture.md to make a change fit: propose it and wait. (7) Before the lane is archived, push everything: archiving drops the container.
