# Changelog

## 0.22.0

- GC-17 (accepted decision 0222): minimum block-time profile/post fields and deterministic Report mode. The built-in Z1 uses the gate-4 measured 7 ms with window 32. Existing project copies remain Off, and Report leaves G-code unchanged. No Slow down or Merge.


All notable changes to `openchuck-app` are recorded here.

## Unreleased

- OUTPUT3 (accepted decision 0327; #312): the `output_preview` module and `Application::output_preview(run)`: the program files exactly as `prepare_output` writes them, each a `PreviewFile` with its final name, bytes, size, SHA-256, line count, `line(n)` and `find(text, from, forward)`; `LineIndex`. `prepare_output` and the preview share one source of file names and texts. No library-family change.

- FOURSTEP (accepted decision 0282; #322; UI-10): **Changed:** `overview::Step` has four values (`Step::Export` removed, `Step::ALL` is `[Step; 4]`, Simulate has no next step); `Overview::health` is the worst of four. New `Overview::export_action` (Post and export, with the old fifth step's rules), `Overview::simulation_action`, `Overview::g_code_written` and `Overview::wrote_g_code_before`; `Overview::primary(Step::Simulate)` is the filled one of the two. `g_code_written` needs the last complete write to hold exactly the enabled operations, so an exported operation since turned off or removed reads "not written". No library-family change.

- MODELCOPY (#385, accepted decision 0307): adding a model file from outside the project folder copies it into `models/` under its content hash, keeping its original name; `ModelStorage` (`Copy` by default, `Link`), `start_prepare_model_as`, `add_model_as`, `start_copying_models` and `finish_copying_models` (the copy runs as a job), `copy_model_into_project`, `copy_linked_models`, `linked_models`, `linked_model_notes` and `is_in_project_folder`; `AppError::ModelCopy` and `AppError::AmbiguousModel`. The toolpath cache key no longer includes where the model is stored or its name, so copying or moving a project keeps every result; the setup sheet's Part row and model messages name a copied model as `part.stl (models/….stl)`; Messages has an information note for each linked model.

- OUTPUT2 (accepted decision 0267; #308, #309, #310): the `output_names` module with `FileNameTemplates` (a per-user setting, `UserSettings::file_names`), the template engine, `fields_list`, `template_problem`, `clean_stem`, `Renamed`, `renamed_warning` and `file_hash`; clashing names (letter case ignored, across every output) get `-2`, `-3` with `OutputFiles::renamed` and `warning` (owner option B, OI-1072). `Application::set_file_name_templates`, `file_name_templates` and `output_files(run)` give every final name or the reason there is none; `prepare_output` writes under those names. Defaults keep the existing names and bytes. **Changed:** `Application::setup_sheet_file_names` returns `Result<[String; 2], AppError>`; new `AppError::FileNames`. The same-run setup sheet lists each program file with its setup, size, SHA-256 and operations, tools and tool changes in order; a sheet written without files says so. New dependency `sha2` (NFR-14).
- #332: every output file is staged in full under a hidden name in the destination folder and published without replacing anything (hard link, or an exclusive claim and rename where hard links are missing); approved replacements stay a staged rename.
- #331: `OutputReport::text` ends with "End of the export result.", so Messages never adds a full stop to the last path.

- FACING review fix: construct whole-setup verification geometry only for modes/extents that require it. Legacy Whole stock/zero-margin generation keeps the existing composite workholding target and pre-scope output; imported stock retains the existing SET-04 refusal.

Stale generated sweeps are not overlaid on edited drafts. Curved outlines are display approximations, never clearance evidence. `FrontPane`/`EndPane` add Facing guides under the0.25.0 API change.

- Actual written verification preserves the accepted Z1 footer after checking its retract against the actual whole setup/configured clearance. Unexpected machine/home/frame changes, unsupported interpolation and excessive coordinate/feed precision refuse export. Default legacy output is unchanged apart from the release-version banner.
- Shared parameter edits use the proposed active schema's range as well as its displayed defaults. Test-only FINSTEP consumer verifies legacy Scallop default0 off / Allowed excess0.01mm on; production adaptive semantics remain FINSTEP-owned. Owner-approved merge order: this FACING PR first, FINSTEP consumes hooks from main afterward.

- Feed and material (decision 0018 item 7): `parameter_values` returns `ResolvedValues` with notes where an operation's value overrides the material's cutting data; a required feed, plunge feed or stepover with no source is refused naming the operation, the material and the tool; `generate_operation` returns `OperationPath` (group and notes). `openchuck-cli` prints regeneration notes as warnings in `validate` and `regenerate`.
- Slice 5, first step (decision 0018): the `operation` module maps an operation to the pathing library (`generate_operation`, `parameter_values` with feed, plunge feed and stepover from the tool's cutting data); regeneration runs every operation in machining order and `Regeneration` gains `notes`; `Application::strategies` and `register_strategy`; errors `UnknownOperation`, `Operation` and `Path`; `Registry` and `Strategy` re-exported.
- Slice 4 (decision 0014): the `tools` module: `check_tools` (shared tool numbers, missing cutting data, library and tool set differences), `default_controller` and `NumberSource` (TL-11), `find_tool`, `describe`, `describe_controller` and `with_custom_profile`, and re-exports of the tool and library types a front end needs.
- Slice 3 (decision 0011): `Command::SetMachine` takes a machine profile; `Application::check_setups` and `find_setup`; `ModelInspection::extent`; the `setup` module re-exports what a front end needs and states the A direction in words.
- `Application::add_model`, `find_model`, `inspect_model` and `inspect_file` as jobs; commands `SetModelUnits` and `SetModelTransform`; the `model` module re-exports the model types a front end needs (slice 2, decision 0010).
