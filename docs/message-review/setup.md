# Message inventory: setup, model, import, project (prefix S)

Scope: every message `crates/openchuck-app/src/overview.rs` `build` makes, and where its text comes from (setup.rs, workholding.rs, the `SetupWarningKind` enum in `crates/openchuck-types/src/setup.rs`, selection.rs, step_sets.rs, ramp_entry.rs, operation.rs, model.rs, tools.rs, machine panel), plus the user-facing messages of `openchuck-import` and `openchuck-project`. Read on `main`, 7 Nov 2026. Test code and doc comments left out.

Abbreviations: MP = Messages panel; SC = Setup checks tab (`Overview::setup_checks`); RW = Results window (run notes, all shown as "Warning:"); tree = the item's status tooltip in the project tree; PW = becomes a `PathWarning` (MP Warning on the operation and also a run note).

How setup messages flow (as read here): each setup finding is pushed three ways at once: an MP row (source = the setup or one of its rows: Machine, Stock, Work offset, Workholding), an SC row and the tree state. None of them names an operation, because they are about the setup. The owner's rule (operation and tool in the text, decision 0522 form) cannot apply as written to a setup-level finding; the proposals below name the **setup and the setting** in the same form instead ("Clearance (setup 'S1'): ..."), and name the operations only where a finding is caused by one (tool too long, tab shorter than a tool, selection reaching a held region).

Link: EditWorkholding for the workholding variants, else ReviewSetup (overview.rs:2150). Source row from `part_of` (overview.rs:1381).
