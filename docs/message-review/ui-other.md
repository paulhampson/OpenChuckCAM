Scope: `apps/openchuck-ui/src` (all non-test files, incl. `shell/*`, `export_panel/*`, `viewport/*`) and the app-crate helpers that write their text (`crates/openchuck-app/src`: `overview.rs`, `form.rs`, `requirements.rs`, `jobs.rs`, `pipeline.rs`, `checkpoints.rs`, `checkpoint_schedule.rs`, `settings.rs`, `export.rs::simulation_out_of_date`, `opflow.rs`, `setup_form.rs`, `machine_edit.rs`, `tool_edit.rs`, `workholding_view.rs`, `preset.rs`, `step_sets.rs`, `model.rs`, `output_write.rs`, `error.rs`, `lib.rs`). Repo state: `main` at e869d932. Read-only.

Not repeated here (the other inventory has them): Messages-panel path warnings, chip **warning** states (`ItemState::Warning` causes), Results-window lines (`run_panel.rs result_lines`), and export-dialog check warnings. Where a row touches one of those, it says so.

"Item named / remedy" is added to the reason of every error row (owner's scope extension).

## Findings that cut across rows (read first)

1. **The shell's status line is never drawn.** `Shell.status` (`apps/openchuck-ui/src/shell.rs:234`) gets "Saved …", "Opened …", "Added …", "Copied N models…", "Recovered checkpoint. Save explicitly to keep these changes.", "Open or create a project before importing a model.", "The selected geometry changed; select it again.", every export outcome status ("Tool numbers changed. Undo with Ctrl Z; save the project to keep them.", "Wrote N files…"), and the status lines of the tool and machine library windows. Nothing outside the tests reads it (`grep` over the non-test code finds only writes). The footer shows the job or "Ready", plus the step note (`shell/frame.rs:1183-1216`). So these confirmations and refusals reach nobody (rows V060-V069). Two of them matter: the recovered-checkpoint reminder (V063) and the refusal to import with no project open (V064), where nothing happens and nothing says why. The library windows also show their own message line, so their texts are not lost there.
2. **The same refusal has two levels.** Step-set refusals (`step_sets.rs`, e.g. "… takes faces, not edges, on a STEP part. Take the edge set '…' out of …") make the operation an **Error** (`overview.rs:1898`, Messages `Severity::Error`). The inspector draws the same text under the Geometry role with an amber **Warning** mark and warning colour (`shell/inspector.rs:1592-1597`) (V154).
3. **Error dialogs have no title and no item, and many show a bare lower-case app error.** `Dialog::Error` has a label and OK, nothing else (`shell.rs:2401`). Undo, redo, `execute` of any command, workholding apply, file replace and selection checks pass `e.to_string()` straight in (`shell.rs:901,917,1639,1944`; `shell/inspector.rs:498,584,902,1149`). These read like "the project has no operation 'x'" or "operation 'A' cannot be generated: …", with no lead saying what failed (V120-V124). Compare the good ones: "The project was not saved: {e}", "The setup was not added: {e}".
4. **NFR-12 wording risk.** Two texts say something is verified or valid:
   - "{name}: Facing coverage complete (verified path geometry)." in the Simulate results (`results_panel.rs:675`) (V090). It is printed for every facing group that carries verification inputs, and it says "verified".
   - The adaptive-height dialog says 0 "may leave places unverified" (V010). This one does not imply safety and is fine.
   The tool profile "✓ Valid: …" is about profile shape rules, so it is acceptable (V187).
5. **Recovery problems are shown as Messages-panel warnings with no source and no action.** These are checkpoint failures, damaged files, another instance, or a copied folder (`shell.rs:766`, `shell/checkpoints.rs`). None is a machining issue, so under the owner's rule none is a WARNING. They are application-health errors or information (V170-V182). This needs an owner call on the class (marked "?").
6. **Operation-state causes are good, but the running cause lacks the activity's object on the bar.** The status bar says "Generating 'op'" through `PipelineActivity::text`, but the jobs list says only the generic label "Generating" (V031, V041). That is minor.
