# Error and refusal texts: inventory (prefix R)

Scope: errors and refusals in openchuck-types, openchuck-project, openchuck-geom, openchuck-post, openchuck-gcode, openchuck-sim, openchuck-import, `crates/openchuck-app/src/error.rs` and the app-level validation errors for the tool library, machine profile, settings and selection sets. The openchuck-path `PathError` refusals and the app's warnings belong to other inventories and are not repeated here.

## How errors reach the user (established while reading)

- **`AppError::user_message()`** (crates/openchuck-app/src/error.rs:142) rewrites only `PathError::Parameter`. Every other variant goes out as its `Display` text unchanged. Only 5 UI call sites use `user_message()`. More than 60 call sites in `apps/openchuck-ui` show `e.to_string()` instead.
- **Error dialog** (`Dialog::Error`, apps/openchuck-ui/src/shell.rs:2401) shows a bare label and an OK button, with no link. Some callers add a lead-in such as "The project could not be opened: {e}", "The project was not saved: {e}", "The setup was not added: {e}", "The name was not changed: {e}", "The operation was not deleted: {e}", "The set was not deleted: {e}" or "The file was not replaced: {e}". Undo, redo and `execute` (shell.rs:901, 917, 1639) show the raw text with no lead-in.
- **Field refusal under a form row** (`form_panel::refusal`, apps/openchuck-ui/src/form_panel.rs:450) capitalises the first letter and adds "Not applied." It does not remove the `invalid <field>:` lead-in, so the internal field path reaches the user (for example "Invalid tool.flute_length: ... Not applied.").
- **The machine editor is the one place that maps `types::Error::InvalidValue`** onto the right field with the reason in plain words (crates/openchuck-app/src/machine_edit.rs:973). If no field matches, it falls back to "`{path}: {reason}.`", so the field path is still shown.
- **Messages panel errors** (Severity::Error, overview.rs) carry a source link. They cover: a failed output report, a failed job ("{label} failed: {e}"), an operation's generate failure, brep-only and refusal texts, "Generating failed: {message}", a selection set that cannot be used (Reselect action), stored workholding that cannot be built (EditWorkholding action), and a model file that is missing, unreadable or cannot be imported.
- **Run and Results window**: a job failure shows `e.to_string()` as `last_error` (run_panel.rs:591). G-code replay failures and static-check findings are listed as Problem lines prefixed with the file name (run_panel.rs:163-182).
- **Export dialog**: a report that is not clean becomes a Blocking check (export.rs:428).

Legend for the columns:
- **level**: refusal/error, or blocking.
- **op?**: whether the text names the operation.
- **item/remedy**: whether the text names the item (op = operation, setup, tool, post, model or file) and whether it says what to change.
- **int**: internal names in the text (field path, snake_case, UUID, Rust type, requirement ID). OI-360 is the open item about these.

None of the texts below needs acknowledgement under GC-16, so the "ack" column is "no" throughout.

## Summary

Counts by proposed class: KEEP-ERROR 91, KEEP-VALIDATION 2, KEEP-STATUS 2, KEEP-INFO 1, KEEP-ERROR? 2 (R15 internal-defect wording; R95 could be information), FLAG 5 (R66 for NFR-12; R71, R101, R102, R103 out of area), TO-WARNING 0, TO-INFO 0 (R95 is the only candidate). Nothing proposed here weakens or removes a check; every proposal changes wording or adds a link only.

Main patterns:
1. `types::Error::InvalidValue` Display ("invalid {dotted.snake_path}: reason") is the single source of most internal names (OI-360). It reaches users raw almost everywhere because only 5 UI sites call `user_message()`, and `user_message()` maps only `PathError::Parameter`. The machine editor (machine_edit.rs:973) already maps the error to a field label; reuse that mapping for tools, setups, simulation and project validation.
2. The app reuses `types::Error::invalid` as a refusal type (tool_library.rs `refuse`, `refuse_spindle`, `add_to_project`, `remove_from_project`, cutting data).
