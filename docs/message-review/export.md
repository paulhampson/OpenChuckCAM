# Message inventory: export, post, G-code checks, simulation (prefix E)

Scope: `crates/openchuck-app/src/export.rs`, `output_write.rs` (OutputReport), `posting.rs`, `note_groups.rs`, the post failures that reach the user from `openchuck-post`, `openchuck-gcode` (check.rs findings, compare.rs replay comparison, reader/interp errors), `openchuck-sim` errors and the app's simulation summaries (`simulation.rs` `warning`, rapid cuts, deviation lines), and the level each gets in `apps/openchuck-ui/src/run_panel.rs` `result_lines` (Results window: Info / Warning / Problem). Main at the time of reading; branch `origin/claude/lane-safetynotice` (decision 0533) rows are marked **in flight**. Test code and doc comments excluded.

How these surfaces work today (read from the code, short):
- **Export dialog "Checks before writing"** (`export_panel.rs:1102`): each `Check` is drawn as "Blocks writing:" (red) or "Warning:" (amber) + text. No link, no action button on any check row. The first blocking check also becomes the "Write G-code" button's disabled tooltip and, at write time, the refusal reason in the OutputReport (`lib.rs:1908`).
- **Results window** (`run_panel.rs:79-244`): Info lines (Generated, Reused, feed-limit summary, replay agreement, stock volumes, deviation), **every** run note as **Warning** (grouped by `note_groups`), G-code findings and replay failures as **Problem**, rapid cuts and overcut as **Problem**. No links on any line. Copied text prefixes "Warning: " / "Problem: ".
- **Run notes** (`regeneration.notes`) are filled from: path notes prefixed "operation '<name>': " (pipeline.rs:361), rapid-cut notes (pipeline.rs:441), the enclosed-material warning (pipeline.rs:532), and post notes (feed clamp, short blocks; pipeline.rs:556). The CLI prints every one of them as `warning: <note>` (cli main.rs:615, 723), with no feed-limit summarising.
- **Post failures** are `AppError::Post`, displayed as "cannot post the G-code: <reason>". Posting runs after `record.working_on(None)` (pipeline.rs:418), so a failed post is recorded with `operation: None` and shown in Messages as `Error` "Generating failed: <message>" with **no source link**, action Generate (overview.rs:1927), and in the export dialog as "The last generation failed: <message> Fix it, then generate again." (blocking).
- **Messages panel** carries, from this scope: the OutputReport (Info, or Error when a file failed; action ReviewExport), the enclosed-material warning (Warning, source = setup, action ReviewSetup), and post failures (Error, see above). G-code findings, replay failures, rapid cuts, overcut and short-block notes are **not** in the Messages panel.
