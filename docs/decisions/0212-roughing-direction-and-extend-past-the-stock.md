## Part A: the direction of the roughing passes (issue 246, F-77)

### Context

Issue 246 asks for a roughing option that runs the passes either along the length of the part (along X, parallel to the rotary axis) or around it. The owner's answers on the issue: today roughing runs along X; "along Y" means passes that **wrap around the part, with the stepover along X**; the option applies to **both the indexed (3+1) and the continuous form** of OP-03; the current direction stays the default so no project or G-code changes (GC-07, NFR-06); plain labels with the axis letters as detail (decision 0114, lane X7b).

What the code does today (decision 0033 items 2 and 3, `openchuck-path/src/roughing.rs`):

- **Indexed** roughing holds A at positions `index_angle` apart and cuts each layer as **lines along X**, stepping across the sector each position faces. So the indexed form runs along the length today.
- **Continuous** roughing (the default form) cuts each layer as **one helix about the rotary axis**, A turning once every stepover of X. So the continuous form already runs **around the part**, stepping along X.

The two forms already run in different directions, so a single default value cannot keep both unchanged. This was raised with the owner (OI-850), who chose option A, the lane's recommendation (relayed by the coordinator, 22 Oct 2026).

### Decision

1. Rotary roughing gains a choice **Cut direction** (`direction`) with three values: `usual for the form` (the default: continuous goes around, indexed along, exactly as today), `along the length of the part` and `around the part`. A choice shows its stored value in the inspector (OI-851), so the values are the plain words themselves; the description carries the axis letters (decision 0114).
2. **Continuous, along the length (new).** Each layer is lines along X at A positions stepped so that neighbouring lines are no more than the stepover apart at the stock's radius (one set of positions for every layer, as axial finishing spaces its passes at the part's largest radius, so each line's floor is found once), and at least four; A turns only between lines. Lines alternate in X (zigzag) so the turn of A happens off the end of a line, as the shared linking services join the passes (OP-14, decision 0033 item 6).
3. **Indexed, around the part (new).** At each fixed A position the tool cuts lines **across the sector** the position faces (along Y, over the same width as the indexed lines along X cover), stepping along X by the stepover and alternating across; A does not move while it cuts (OP-15). In 3+1 the part cannot turn while the tool cuts, so this is the only "around" the indexed form has.
4. **Everything else is shared, as today.** The layers, the floor with the stock to leave (decisions 0058, 0205), the remaining-stock awareness, the region constraint (decision 0043), the held region (SET-09, decision 0161: lines are cut short at the keep-out intervals and `keep_clear`/`check_clear` still refuse a path that enters them), the tabs (OP-21: part of the surface the tool is dropped on), the entries (decision 0026), the links (OP-14) and the F word limit (decision 0076) apply unchanged.
5. **No project format change.** A strategy parameter is a free map entry (work breakdown, "Project schema ordering" item 3), so no schema number is taken. An operation saved without the value takes `form`, so every existing project gives byte-identical G-code; no golden file changes.

## Part B: extending past the stock, and facing (issue 211, F-55)

### Context

Issue 211 asks for an option that lets a path run past the edge of the stock by a set distance, so the tool clears the stock fully (facing the end of the stock without a skin or witness line). There is no requirement for it (a search of `docs/requirements.md` finds none). The owner's decision, relayed by the coordinator: **option C**, an **"Extend past the stock"** option on the roughing and finishing strategies (off by default; the distance defaults to a fraction of the tool diameter, with limits; the user chooses the stock ends) **and** a simple dedicated **Facing** strategy built on it. The owner's earlier answers on the issue: the lane decides which strategies can honour it and says why for each that cannot; the user chooses which ends or sides; a distance up to the full tool diameter must be allowed. (The owner's issue comment said "not a new dedicated facing strategy"; the later relayed decision, option C, adds one. This record follows the later decision and asks the owner to confirm it, OI-852.)

OP-21 is the last operations ID on `main`; OP-23 is proposed on the STEPALL branches (face sets), so this record took **OP-24**, which the owner agreed at P1. Today rotary roughing covers the part's length plus three tool radii and the stock to leave at each end (decision 0033), and stock beyond that is not touched; finishing passes end where the part ends.

### Requirement (as the owner agreed it, at P1)

> **OP-24 (P1).** Extend past the stock, and facing: roughing and finishing strategies that cut along or around the part can carry their passes past the edges of the stock by a distance the user sets, at the ends of the stock (and, for a strategy whose passes run across, its sides) the user chooses, so the tool leaves the stock fully and leaves no skin or witness line. The option is off by default; the distance is measured from the edge of the stock to the near side of the tool and may be set from zero up to the tool's diameter. A Facing strategy cuts the stock down to a flat face at chosen A positions, or round to a chosen diameter, using the same extension. No extension enters the held region (SET-09), cuts a tab (OP-21), crosses the clearance geometry (SET-06) or goes beyond the machine's travel; where one would, generation says which and writes no path.

Verification-plan row as proposed (the row added to `docs/verification-plan.md` is this one at P1, naming the tab and the travel amount as built):

> | OP-24 | P2 | T | Unit, system | On a cylindrical stock longer than the part and a box stock: with the option off every golden file is byte for byte unchanged (GC-07); with it on, each chosen end (and side) is cut until the tool's near side is the set distance past the stock edge, and the simulated stock shows no skin at that edge; the distance is refused below zero or above the tool diameter; an extension towards a held region, through a tab, or beyond the machine's X travel is refused with a message naming it and no path is written; Facing leaves the stock flat at the chosen A positions (or round at the chosen diameter) to within the tolerance, with the stock to leave on the part where the part rises above the face |

### Design (built, with the refinements under "As built")

1. **Parameters**, the same on every strategy that honours the option: `extend` "Extend past the stock", a choice of `none` (default), `both_ends`, `start_end`, `far_end`; `extend_sides` "Also past the sides" (a flag, only on strategies whose passes run across: indexed roughing around the part, Facing on a flat); `extend_distance` "Distance past the stock" (mm, from 0 up to the tool diameter, from the stock edge to the tool's near side).
2. **Default distance.** Written into the operation when the option is turned on, as decision 0205 does for the stock to leave: **10 percent of the tool diameter, rounded to 0.05 mm, at least 0.1 mm** (0.3 mm for a 3.175 mm tool, 0.6 mm for 6 mm). Limits: 0 to 1.0 times the tool diameter (the owner's "up to the full tool diameter").
3. **Which strategies honour it, and why not the others:**
   - **Rotary roughing**, both forms and both directions: yes (ends; sides for indexed around the part). The passes already run beyond the part; the extension carries them to the stock's ends.
   - **Helical, axial and indexed finishing**: yes, ends only. Past the end of the part the pass runs on at the height of its last point, flat, until the tool clears the stock end (the material there is what the finishing pass would otherwise leave as a step).
   - **Facing** (new): yes, ends and sides; it is built on the option.
   - **Simultaneous 4-axis finishing: no.** Its tool axis follows the surface normal (OP-06); past the stock there is no surface to orient the tool to, so an extension would be a guess.
   - **Rest machining and pencil clean-up: no.** They cut only where an earlier tool left material on the part; past the stock there is none.
   - **Edge and curve following: no.** The path follows chains on the part; an extension would leave the chain.
   - **Swarf: no.** The flank follows a ruled wall of the part; carrying it past the wall's end changes the wall it cuts. (Its own boundary options, decision 0176, already cover a pass that runs past a boundary.)
   - **Radial drilling: not applicable.**
4. **Facing strategy.** A roughing-group strategy, "Facing": `shape` `flat` (at A positions from an angle list or a count, the indexed form's way) or `round` (turned down to a diameter, the continuous form's way); `face_height` for a flat (the distance of the face from the rotary axis) or `diameter` for round; layers by the stepdown from the stock top to the face. It covers the **whole stock**, not only the part, and the extension applies at its ends (and sides for a flat). Where the part with its stock to leave rises above the face, the tool follows the part, as roughing does (OP-12); it never cuts below it. It reuses the roughing layers and the remaining-stock field.
5. **Safety (NFR-12, NFR-07).** An extension towards an end that is held (SET-09) is refused, not cut short, with a message naming the end ("the start of the stock is held by the chuck, so the path cannot extend past it"); the keep-out checks stay as they are. Tabs are part of the surface the tool is dropped on, so no extension cuts one. The application checks the extended path's X range against the machine's X travel (less the work offset) before the path is accepted, and refuses it with the amount it is over; the post's static check stays. Links still go through the clearance geometry (OP-14).
6. **Deterministic** (GC-07, NFR-06): the extension adds points by arithmetic on the stock's size and the set distance only.
7. **No project format change**: parameters are a free map entry; no schema number.

### As built (22 Oct 2026)

Built on `claude/lane-cutopts`, in `openchuck-path` (`extend`, `facing`, and the roughing, helical, axial and indexed modules), `openchuck-sim` (`DexelStock::x_extent`) and `openchuck-app` (`operation.rs`). Refinements of the design above, each for the reason given:

1. **The values are plain words**, as for the cut direction (OI-851): `extend` is `no` (default), `both ends`, `start end` or `far end`; `extend_sides` is a flag; `extend_distance` is in millimetres.
2. **The default distance is derived, not written.** The schema's own default is 0 mm (a parameter schema cannot know the tool), and the application gives the strategy a tenth of the tool's diameter (`extend::default_distance`: rounded to 0.05 mm, at least 0.1 mm) wherever the operation has no value of its own, and the inspector shows that value with its source as the default, as it does the crease angle on a STEP part. Nothing is written into the operation, so the project holds only what the user set; a changed tool changes the default with it. A value above the tool's diameter is refused by name; below zero the schema refuses it.
3. **Sides only on Facing's flat.** On rotary roughing the side of an indexed sector is not an edge of the stock (only a 180 degree index reaches it), so the sides flag is offered on Facing only, whose flat face spans the stock's chord.
4. **Roughing past an end** widens its range to the extended end, and over the stock past its end a node is cut while there is material at the stock's end at that layer (the remaining-stock field is read at the end, not past it), so the tool carries on past the edge rather than stopping where the material does. The finishing strategies add a straight run-out along X from a pass end at the part's end, at that point's height along the tool axis and its A, dropped on the target so it rises over a tab or held solid rather than cutting it.
5. **Facing** takes `shape` (`flat` or `round`), `size` ("Finished size": the face's distance from the axis for a flat, the diameter for round; required), `angles` (flat; default `0`) and roughing's stepdown, largest angle step, start angle and smallest cut. It covers the stock's whole length (`StockModel::x_extent`, a new provided trait method; the analytic and simulated stocks answer it). A size that leaves nothing to face, and an empty angle list, are refused by name. It takes no selections.
6. **Held end and travel.** An extended end on the side of a held region is refused with a message naming the end (SET-09), whatever the distance. The application refuses an extended path whose fed moves go beyond the machine's travel along the rotary axis, naming the end and the furthest amount over; a path without the option is not checked here (the post's static check still runs on every program).
7. **Library API.** New modules, constants, a provided trait method and a new strategy only, so no breaking change and no version bump. The changelog says so.

Tests (named for OP-24): `openchuck-path/tests/extend.rs` (off by default and unchanged, each strategy past each end, the distance limit, the held end, Facing flat, round, following the part, the sides, the refusals and the registration), `extend::tests::req_op_24_the_default_distance_is_a_tenth_of_the_tool_diameter`, `openchuck-sim/tests/facing.rs` (no skin at the ends after Facing round; roughing past the far end clears it and leaves the start), `dexel::tests::req_op_24_the_stock_ends_are_where_its_material_is`, and in `openchuck-app/tests/operation.rs` the default distance from the tool and the travel refusal.

## Alternatives considered

- **Part A: two values with default "along the length of the part"** (the owner's words; option B). Not chosen: every existing continuous roughing operation would change direction and G-code unless a schema migration wrote `around` into every stored one. **Fold it into the Form choice** (four values): no new parameter, but the form and the direction are two ideas and the inspector reads better with two choices. Both were put to the owner, who chose A (OI-850).
- **Part B: extend by the tool's centre** rather than its near side. Rejected: "past the stock" reads as clear of it; a distance from the centre means the user must add the radius.
- **Part B: cut short at a held end instead of refusing.** Rejected: the user asked for an extension there; cutting it short silently is the divergence NFR-07 forbids.
