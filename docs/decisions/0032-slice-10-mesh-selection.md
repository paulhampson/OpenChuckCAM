## Decision (accepted)

1. **Selection algorithms (item 2; UI-04).** `openchuck_geom::select`: `flood_fill` (every triangle connected through shared edges), `flood_fill_by_angle` (a step across an edge is taken when the two normals differ by at most an angle, which gives a smooth patch such as one face of a block), and `select_by_direction` (every triangle whose normal is within an angle of a direction; a cone test, not connected). Each returns a sorted `TriangleSet` and a bad seed, angle or direction is an error. Degenerate triangles have no normal and are never crossed or picked by angle. `submesh` builds the part of a mesh a set names. "Select by angle" is read as both of the first two; the requirement does not say which.
2. **Sets and their edits (item 3; UI-05).** Sets are made and changed through `Application::save_selection` and `edit_selection` (add, remove, replace, rename), each one undoable command through the existing `Add` and `Replace`. A set keeps the model hash it was made against; editing does not make it current. `edit_selection` returns the operations that use the set. `Project::operations_using` and `file::selection_inputs_hash` give the same answer to a front end or a cache: the hash covers the roles, and for each set its model, model hash and triangles, so it changes for exactly the operations that use an edited set, not for a rename. The pipeline has no cache yet (it regenerates everything), so "marks for regeneration" is this query and this hash, which slice 9's cache key combines with the operation's other inputs (architecture section 6).
3. **Persistence (item 4; PRJ-06).** Unchanged from slice 1: one TOML file per set, triangles sorted. New: the operation file gains `boundary`, `avoid` and `check` (written only when set, so existing projects and golden files are unchanged but for the schema number). This is a format change and so takes **project schema 7**, claimed in the work breakdown's table ("a format change is a bump, however small"; schema 6 is slice 8's `enabled`, decision 0029): `SCHEMA` is 7, with a migration from 6 that changes only the number. Triangle `i` is facet `i` of the file and placement keeps the order, so a set survives a change of units, placement or mirroring.
4. **How a region reaches the pathing library (item 5; OP-02).** `RegionConstraint`, plain data and ports (INT-01, INT-02), is given to `Strategy::passes_in_region` through `generate_in_region`. Nothing is added to a public struct (`StrategyInput` is built by literal by hosts, so a field would fail `cargo-semver-checks`); the two trait methods and the function are additions, and the default `passes_in_region` refuses. The app maps each role to the union of its sets' triangles and gives the library a `MeshSurface` for each, and a `Window` for the boundary. The strategy still drops its tool on the **whole** part, so a cut next to the region never gouges the rest; the constraint only decides where a cut may be made. A cut is allowed when its contact lies on the region (if any), inside the boundary (if any), not on an avoid surface, and the tool is not touching a check surface. "On" is within 1e-4 mm. A tool not allowed to cut leaves a gap in the pass, which the shared services link (OP-14). A constraint that leaves nothing to cut is an error ("the strategy produced no cut for this selection"), not an empty result.
5. **The roles (OP-02).** `Operation::selections` (existing) are the sets it machines; new `boundary` (one set), `avoid` and `check` (lists). Several sets in a role are their union. Proposed meanings, since the requirement names the terms and not their behaviour:
   - *avoid surface*: never cut; the tool may pass over it.
   - *check surface*: the tool must not touch it. For helical finishing, which rides the surface, this is the same as avoid in effect; the difference is in what triggers it (the contact on an avoid surface, any touch of a check surface), and it matters for strategies that cut away from the surface (roughing, slice 14).
   - *containment boundary*: the window of the set's triangles in the development about the rotary axis: an interval of X and the smallest arc of angle about X that holds its vertices. A ring of vertices (at least eight, with no gap more than four times the typical gap) is a full turn and does not limit angle. A boundary drawn as a curve on the unrolled surface needs the region offsets of slice 12 (OI-137).
6. **Helical finishing honours it.** `Strategy::honours_region` (default false) is true for helical finishing, which implements `passes_in_region`. An operation with selections on a strategy that does not honour them is refused, naming the strategy: a strategy that ignored the region would cut outside it (verification policy 8). The helical points are placed no further than 0.1 mm of path apart at the part's largest radius when a constraint applies, so a feature of a selection narrower than that may be missed (OI-138); the limit of the allowed region is then found by bisection (twelve steps) so a cut reaches the edge of the region to a small fraction of the step, and a gap narrower than the default angle step is found and left uncut (test `req_op_02_a_small_avoid_patch_between_two_default_seeds_is_not_missed`, which fails without the spacing rule).
7. **A reference that cannot be resolved (design refinement; OP-02).** Generating an operation resolves each set against the setup's part and stops with an error naming the operation and the set when: the set was made on a different model; the model file's hash is not the one in the set (the file changed); a triangle is beyond the model; the set selects nothing; or the set is a face or edge selection on a mesh (which the project already refuses to hold; it is also refused here for a hand-edited file). Nothing is dropped silently. The visible warning of the review checklist is the UI's (slice 8 onwards, OI-139): the error text is worded for it.
8. **Where the code is.** Algorithms in `openchuck-geom` (architecture 5.4); `RegionConstraint` and `Window` in `openchuck-path` (architecture 5.2); the set roles and hash in `openchuck-project` (5.6); the commands, the resolution and the strategy check in `openchuck-app` (5.7). No new dependency.

## Alternatives considered

- **Region as a filter over the surface source, so the strategy sees only the selected triangles:** simplest, and wrong: the tool would be dropped onto the selection alone and gouge the unselected geometry next to it.
- **Roles as a list of (set, role) pairs on the operation:** more general, a bigger schema change; four fixed roles cover OP-02 as written.
- **No schema bump for the new operation fields:** an addition that is absent when unused changes no existing file, but the work breakdown's rule is that any format change takes a number, so it is schema 7.
- **Hashing the whole operation for the cache key now:** slice 9 builds the cache; this record gives it the selection part, which no one else can compute.

## Evidence

- `openchuck-geom/tests/select.rs`: `req_ui_04_*`: counts on a cube (flood fill 12; by angle 2 at 30 degrees, 12 at 90; by direction 2, 10, 12), a smooth ramp with one sharp joint, degenerate triangles, bad input.
- `openchuck-path/tests/region.rs`: `req_op_02_*`: cuts stay on a region and reach its edge, an avoid surface and a check surface are never cut or touched, a boundary limits X and angle, a small avoid patch between two seeds is not missed, an empty constraint changes nothing (byte for byte), and a constraint that leaves nothing is an error.
- `openchuck-app/tests/selection.rs`: select, save, close and reopen gives the same set with the model's hash; saving and editing are undoable and checked; editing a set changes the selection hash of exactly the operations that use it; helical finishing on a cube cuts only the top face, never the top face as an avoid surface, never touches it as a check surface, and stays inside its boundary; each unresolved reference stops the operation with its name; a strategy that ignores regions is refused.
