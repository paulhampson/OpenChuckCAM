# 0056: STEP parts through the application pipeline: B-rep placement, exact surfaces, drilling and B-rep edge following (lane Z; OI-219, OI-226)

- **Status:** proposed (17 Oct 2026). Lane Z, built on `claude/lane-z-brep-pipeline`. Not accepted: only the project owner accepts a record (decision 0049). It changes no requirement, no architecture rule and no project file format, and no library-family API. The choices a reviewer is most likely to change are items 2 (every strategy on a STEP part sees the exact B-rep surface) and 4 (the B-rep crease default when the operation sets none).
- **Date:** 17 Oct 2026.
- **Open items** are tracked in [docs/open-items.md](../open-items.md): OI-232 to OI-236 are new; OI-219 and OI-226 are closed by this record's acceptance (OI-219 once gate 3 has replayed the `drilling` program in CI).

Numbering: the orchestrator assigned records 0056 to 0060 and OI-232 to OI-236 to lane Z. This record takes 0056 and OI-232 to OI-236; 0057 to 0060 are unused. Lane Z takes no project schema number.

## Context

Lanes R ([decision 0051](0051-slice-18-radial-drilling.md), radial drilling) and P ([decision 0053](0053-slice-16-edge-following-brep.md), `BrepEdges`) built library strategies for B-rep parts, and both stopped at the application: the pipeline read every model as a placed triangle mesh (`placed_mesh_hashed`) and refused a STEP model (`ImportError::NotSupported("STEP")`), so a STEP file could not even be added to a project. OI-219 asks for a drilling reference job through the application so gate 3 can replay it; OI-226 asks for a path from a STEP part to a `BrepSurface` and for the B-rep edge source to be chosen, with the operation's `crease_angle` and `min_length` passed to it.

The STEP importer already runs the kernel in a worker process (decision 0003), so the application needs no kernel to read STEP; only the tests that read a real STEP file need it (`kernel-tests`). The project format already holds B-rep selections: a selection set's target may be `Faces` or `Edges` (schema 1, architecture section 5.5), and the project refuses a triangle set on a STEP model. What is missing is reading them in the pipeline, and making them in the viewport (11b, lane O).

Records read: 0003, 0017, 0027 (STEP import and exact faces), 0042 and 0045 (the composite target and its wiring), 0047 and 0053 (edge following), 0051 (drilling), 0048 (API changes before 1.0), 0054 (register merges). Open items checked: OI-204 (stored edge-chain selection kind, lane O, schema 12; not touched), OI-28 (golden files that depend on kernel tessellation), OI-219, OI-226, OI-227.

## Decision

1. **A STEP part is placed as a B-rep (IMP-05).** `openchuck_geom::transform::transform_brep` maps a `BrepModel` by the placement's affine map, keeping every face, edge and vertex ID: frame origins are mapped and frame axes mapped and divided by the scale, so they stay orthonormal; radii scale; the parameters that are lengths (u and v of a plane, v of a cylinder and a cone) scale in the UV bounds and trim loops, so a (u, v) names the same place; B-spline poles are mapped. A mirror makes the frames left-handed, which the exact evaluators accept (decision 0017), and flips each face's `reversed` so its normal stays outward; the tessellation's winding is reversed as for a mesh. `brep_placement` takes the map from the joined tessellation, so `CentreOnRotaryAxis` centres the same triangles the viewport draws. `openchuck-geom` holds transforms (architecture section 5.4); the function is new, so nothing breaks.
2. **Every strategy on a STEP part sees the exact surface (IMP-02; the choice a reviewer is most likely to change).** The pipeline (`openchuck-app` `model::placed_part`) keeps the placed B-rep beside its joined tessellation, and `generate_operation` gives the strategy a `BrepSurface` for a STEP part and a `MeshSurface` for a mesh, joined to the held regions and tabs as before (decision 0045). Tool drops on a `BrepSurface` go through its joined tessellation (decision 0017, OI-81), so the drop-based strategies cut as they would on the tessellation; points, normals, projections and holes are exact. Everything else that needs triangles (drawing, the mesh checks of the inspection, the workholding checks, the simulation's deviation target) uses the joined tessellation, so a STEP model can be added, inspected, drawn and simulated like an STL.
3. **Selections on a STEP part are its faces and edges, read from the existing targets; no format change.** A `Faces` set in an operation's selections chooses the holes of radial drilling (`BrepSurface::with_faces`, decision 0051 item 2); an `Edges` set chooses the edges of edge following (`BrepEdges::with_edges`, decision 0053 item 1). Each set must be on the setup's part, made on the current file (its content hash, PRJ-06), and name faces or edges the model has. Everything else is refused with a message naming the operation and the set, never dropped (OP-02): face sets for any other strategy, edge sets for any strategy but edge following, and boundaries, avoid and check surfaces on a STEP part (OI-233). Triangle selection jobs (flood fill, by angle, saving a triangle set) refuse a STEP model: it is selected by face and edge (architecture section 5.5). Making face and edge sets in the viewport is lane O's (11b); until then they are made by command.
4. **Edge following on a STEP part follows its B-rep edges, with the operation's values (OI-226).** The source is chosen by the model's kind: a STEP part gets `BrepEdges` (all real edges, or the chosen ones), a mesh keeps `MeshFeatureEdges`. The operation's shortest chain (`min_length`) is passed as it is. Its `crease_angle` is passed when the operation sets it; when it does not, the B-rep default of 1 degree applies (decision 0053 item 2) rather than the schema's 30, which is the mesh's, and the parameter form shows 1 as the default for a STEP part, so what the form says is what runs. The library's warning that the crease angle and shortest chain are not used with a given source is not shown, because here they are. A crease angle of 0 (keep tangent edges, `with_crease(0.0)`) cannot be set from the operation: the parameter's range excludes 0, which on a mesh would make every triangle edge a crease (OI-232).
5. **The `drilling` reference job runs through the application from a STEP file (OI-219).** `crates/openchuck-app/tests/step_pipeline.rs` (`kernel-tests`) copies the OpenCASCADE fixture `rotary_blank_drilled` (a 24 mm rod with a 6 mm through hole) into a project, places it turned 30 degrees about the rotary axis, and drills it with a 6 mm, 118 degree drill in oak on the Makera Z1 in pecks of 8 mm (full retract). Both posts pass gates 1 and 2, the program is identical at 1, 2 and 4 threads, and it matches `testdata/golden/reference/drilling_makera-z1.nc` and `drilling_linuxcnc.ngc`. `cargo xtask replay` picks the LinuxCNC program up from the folder, so gate 3 replays it with the others. The STEP kernel CI job runs the file on all three platforms; a golden file that differs between platforms (OI-28) would show there. One hole at one A is a modest job; a fixture with holes at several angles is OI-234.
6. **No library-family or format change.** `openchuck-geom` gains `transform_brep` and `brep_placement` (new items); `openchuck-app` changes inside (`generate_operation` now accepts STEP parts). The library family is unchanged, so `cargo-semver-checks` has nothing to flag and the workspace stays 0.8.0. No project schema number.

## Alternatives considered

- **The exact surface only for drilling and edge following, the tessellation for the rest:** the smallest change, and each existing strategy keeps the surface its tests ran on. Rejected as the recommendation because IMP-02 and the architecture (section 4) put B-rep faces behind `SurfaceSource` for every strategy, and with tool drops on the tessellation the difference for the drop-based strategies is small; the owner may prefer it until each strategy is checked on a `BrepSurface` (the unit test here runs drilling and edge following; helical finishing on a STEP part is not separately tested).
- **A new parameter for the B-rep crease angle, or a schema default of 1:** a parameter would split one idea in two; changing the default would change every mesh operation's feature edges. Reading the operation's value when set, and the B-rep default otherwise, keeps one parameter and both defaults.
- **Allowing 0 in the crease angle's range:** 0 on a mesh selects every triangle edge, which is never meant. Left for the owner (OI-232).
- **A reference job built from the closed-form blank of `openchuck_testkit::brep` without the kernel:** it would run in every CI run, but it would not go through a STEP file, the importer or the placement of an imported model; the closed-form path is covered by unit tests in `openchuck-app` instead (below).
- **A fake STEP worker for kernel-free integration tests** (a script that writes a canned answer): portable only to Unix and needs an environment variable set inside the test process, which the workspace's `unsafe_code = "deny"` forbids; the unit tests hand the placed part to the pipeline directly (`generate_with_part`).
