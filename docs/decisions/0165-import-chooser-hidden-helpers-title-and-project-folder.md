# 0165: STEP in the model chooser, hidden helper programs, window title and project folder (lane BUG-IMP; #220, #221, #218, #219; OI-581 to OI-584)

- **Status:** accepted by the project owner (20 Oct 2026), on the owner's instruction given in the lane BUG-IMP session. Items 3 and 4 follow the owner's choices relayed by the coordinator session (title format; warn and ask for an existing folder).
- **Date:** 20 Oct 2026.
- **Open items:** OI-581 and OI-583 (closed), OI-582 (owner check on Windows), OI-584.

## Decision

1. **The model chooser offers STEP (#220, IMP-01, IMP-02, IMP-06).** The Browse dialog's filter is "3D models (STL, STEP)" with `stl`, `step` and `stp` in either case; the path box hint says "model file (STL or STEP)". A STEP file chosen is imported by the STEP worker of decision 0027. A build with no STEP reader says so in plain words: "this build cannot read STEP files: the STEP reader program … was not found next to the application" (NFR-07).
2. **Every helper program starts without a console window (#221, NFR-17).** The only helper program the application starts that is not a deliberate file browser is the STEP worker (`openchuck-import`, `run_worker`); it was started without `CREATE_NO_WINDOW`, so each import of a STEP, including the re-imports a STEP project makes when it is opened or checked, flashed a console window on Windows. It now starts with that flag on Windows and with none elsewhere; its standard error goes to a file in its scratch folder, and the tail of it is added to the error message the application writes to the log file (#155). The Open log folder and Open folder buttons start the system file browser on purpose and keep their window. The `git` probe of the build script runs at build time only. The check on a real Windows desktop is the owner's: OI-582.
3. **Window title (#218; owner's choice, relayed by the coordinator, 20 Oct 2026).** `OpenChuckCAM - Blisk* - <path>`: the application name first, the project's name with a `*` when there are unsaved changes, then the project folder; with no project open, `OpenChuckCAM`. A path longer than 70 characters is shortened in the middle, keeping the drive (or root) and as much of the end as fits, so the project's own folder always shows. The full path is in a hover tooltip on the title-bar project name and in the About window. The path appears only in these local places: never in the G-code or the setup sheet, and nothing leaves the machine.
4. **New project folder (#219; the owner's rule for an existing folder, relayed by the coordinator, 20 Oct 2026).** New project asks for a *parent folder* and a project name, shows the *folder name* it will create, and creates `<parent>/<folder name>` holding the project. The project keeps the name as typed. No file layout or schema changes: a project is the same folder of text files; only which folder is made changes (no schema claim).
    - **Folder name** (`openchuck_project::new_folder::folder_name`, the same on every platform, NFR-02): `< > : " / \ | ? *` and control characters become `_`; invisible characters (zero-width, bidirectional controls, soft hyphen, byte-order mark, variation selectors) are removed and other space characters become an ordinary space; leading and trailing spaces and dots are removed; a Windows device name (`CON`, `PRN`, `AUX`, `NUL`, `COM0` to `COM9`, `LPT0` to `LPT9`, also with the superscript digits, with or without an extension, any case) gets `_` in front; at most 100 characters; nothing left gives `Untitled`.
    - **A folder that does not exist** is created.
    - **A folder that exists** gets a two-choice dialog, "Folder already exists": *Use the existing folder* or *Change the name* (back to the form with what was typed). Nothing is written before the answer.
    - **Safety rule for "use the existing folder" (NFR-07).** Saving a project removes `machine.toml` and the `.toml` files in the item folders it does not own, so an existing folder is *usable* only if it holds none of `project.toml`, `machine.toml`, `setups`, `tools`, `selections`, `operations`. Any other files (a STEP file, a readme, a `.git` folder) may be there and are never touched: using the folder only adds the project's files. If the folder holds any of the six names, the form says so plainly ("already holds an OpenChuckCAM project or its files (…). Nothing is overwritten. Choose another name.") and OK stays off: there is no way to overwrite or delete. A file with the folder's name is refused the same way. `file::create` enforces the same rule, so no caller can get past it (this also stops "Create a project here?" on Open from deleting a stray `machine.toml`).
    - **Not built:** an "open that project" button (proposed only); a name suggestion; Unicode normalisation to NFC and look-alike (homoglyph) characters (OI-584).
    - **Save as and Open** are unchanged. The cleaning rule is a shared function, so exports, setup sheets and tool library files can use it later (not changed here).
