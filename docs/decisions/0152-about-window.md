# 0152: The About window shows the build, the licences, and a Copy action (lane BI)

- **Status:** accepted by the project owner on 19 Oct 2026, given directly in the lane BI session, with decision 0151, which it depends on (OI-443, OI-444). The licence box's content is settled with it (OI-445 closed). Lane BI, GitHub issue #139.
- **Date:** 19 Oct 2026.
- **Open items** are tracked in [docs/open-items.md](../open-items.md): OI-445 is new.

Numbering: see decision 0151.

## Context

The About window (Help > About OpenChuckCAM…, `Dialog::About` in the shell) shows the version, one line on the licence and the NFR-12 notice. The owner asked for the build facts of decision 0151, a scrollable licence text and a Copy button that copies the build information only. The interface specification has no section for it (supporting windows are 12.1 to 12.3).

Requirements touched: NFR-16, NFR-10, NFR-12, UI-14, NFR-15.

## Decision (accepted)

1. **Specification section 12.4, About window** is added to `docs/ui-design/ui-specification.md` in this pull request: a modal dialog in the style of the other dialogs, with, from the top, the name; the licence line; the NFR-12 notice; the "Build" block (the text of decision 0151 item 5, monospace); the "Licences" box; a footer with **Copy build information** (secondary, left) and **Close** (the one primary button, bottom right, specification section 5).
2. **The Licences box** is a read-only, monospace, scrollable text box (about ten rows, scrolling beyond). It holds, from the files the repository ships in `LICENSES/` (NFR-10): the AGPL-3.0-or-later text, the IBM Plex notice, the SIL OFL 1.1 text and the OpenCASCADE notice and source offer, and a first line saying that the licences of the third-party Rust crates are in `THIRD-PARTY-NOTICES.html` in the folder the program came in. The texts are compiled in (`include_str!`), so the box works offline and from any folder. `THIRD-PARTY-NOTICES.html` is generated by `cargo about` in the release workflow and is not in the tree, so its content is not compiled in (OI-445).
3. **Copy** puts exactly the build text on the clipboard (nothing from the notice or licence), and does not close the window.
4. **Keyboard.** Tab visits the licence box, Copy, then Close, in reading order; the box scrolls with the arrow keys and the wheel; Enter presses the button that has focus. Copy's tooltip opens on keyboard focus as well as on hover (specification section 16). Colours and type come from the theme tokens (IBM Plex Sans and Mono).
5. **Code.** A new module `apps/openchuck-ui/src/about.rs` draws the window. The only change in `shell.rs` is the `Dialog::About` arm, which now calls it. No menu changes: the Help menu already has the item.

## Alternatives considered

- **Compile the `cargo about` output into the binary.** It needs `cargo-about` at build time, which contradicts building offline from a clean tree. Rejected; the archive carries it (decision 0031 item 3).
- **A separate window beside the main one.** The dialogs are modal in the main window (specification section 3). Rejected.
- **Copy as the primary button.** The window's job is to inform; Close is the one primary action (section 5).

## Consequences

- `docs/ui-design/ui-specification.md` gains section 12.4. The specification's mock-ups are not re-rendered (no board for this window).
- The binary grows by about 40 kB of text.
