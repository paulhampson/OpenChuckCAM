## Context

Accepted 0221 requires gates 1–4 for the first-cut project before gate 5. The existing branch includes its LinuxCNC golden in gate 3, but both the driver and wrapper have a 900 s timeout. The program has 1,727.333 s nominal fed motion before rapids, acceleration and tool changes; one original rapid alone takes about 228 s under the simulator's velocity limit. The unchanged whole-program replay cannot finish under those limits. AGENTS.md requires an owner disposition for an uninstrumented test exceeding ten minutes. The owner authorized bounded chunks preserving every original move and explicitly checking modal state and continuity at each boundary.

## Decision

1. **Split the verification fixture, preserving the original program.** Before assigning CI shares, `cargo xtask replay` expands `first_cut_linuxcnc.ngc` into deterministic, independently runnable simulator chunks. Contiguous original source lines appear exactly once across their recorded source ranges, in order. No original move is dropped, resampled, shortened or given a different feed. Chunk preparation leaves the production file and its golden bytes unchanged. A released main integration may update the input under its own accepted decisions; each runtime result names its exact source revision/hash. Added initialization, pause and termination commands belong only to temporary verification fixtures.
2. **Bound each execution.** The planner targets at most 300 s estimated simulator time per chunk, including 45.05 s startup allowance and a conservative acceleration allowance. Timing uses only `checks.ini` simulator limits, not an inferred Z1 limit. Both the wrapper and the driver's chunk limit are at most 600 s, honoring a smaller explicit timeout. An atomic move that cannot fit is refused; a timed-out chunk stops without an automatic long-test retry. A comparison failure may have the existing one repeat; failure on a repeat remains failure.
3. **Restore and check coordinates and modes.** Initialize each simulated joint's HOME/HOME_OFFSET at its original boundary coordinate, preserving travel, velocity and acceleration limits. This avoids added travel from A0 to a large accumulated A coordinate. Restore the supported G90/G21/G17/G61/G54/G94 modes, G0/G1 motion mode, modal F, tool, spindle state and S. The narrowly defined splitter refuses unsupported codes or syntax rather than guessing. It does not replace the independent G-code reader/replay.
4. **Verify actual boundary states.** At a simulator-only M0 before and after the original source range, with `M66 E0 L0` immediately afterwards as a LinuxCNC interpreter queue barrier, check commanded and actual XYZA against the expected original boundary (0.001 mm/degrees), required active G modes, F when set, tool, spindle enable/direction and S, zero G54/G92 offsets and XY rotation. The barrier prevents the next original line from changing interpreter-reported F/modes while the M0 is paused. An initial bounded attempt exposed that read-ahead (for example, expected F18.1 but reported the next line’s F299.9); it was stopped and retained, not waived. Missing, extra or mismatched checks fail. One chunk's expected end must equal the next chunk's expected start; tests check exact contiguous source reconstruction and continuity. The independent `gcode-sim --source-lines FIRST:LAST` comparison checks each fixture against the original unsplit program: it replays the full original prefix to verify both actual states, then compares the original moves in the selected range. A mutually consistent fixture and wrong manifest cannot mask a source-boundary error. It uses the existing tolerance (0.1 mm/degrees; final position 0.001). No comparison tolerance is relaxed.
5. **Keep all execution units in CI.** Expand first, then deal chunks and other programs over the existing shares. Every unit belongs to exactly one share; no empty share passes. This lets a runner check bounded units while retaining the entire first-cut source. Per-attempt wall timings and first comparison-failure reports are retained. Reports retain actual boundary snapshots; artifacts also retain fixture text, expected states/source ranges and simulator configuration. Python 3 is required on the host for the pure boundary-helper unit tests; the LinuxCNC image already supplies Python for the driver.
6. **State the limits.** Separate fixtures introduce stops and fresh interpreter initialization, so this is not evidence of uninterrupted full-program dynamics. Exact-stop G61, source coverage and actual state checks constrain that boundary risk. These checks supply subsequent software evidence; they do not establish the original pre-cut gate ordering or replace the owner's physical result, waived air cuts or unchecked OI-267. Generated G-code remains the user's responsibility to verify (NFR-12).
