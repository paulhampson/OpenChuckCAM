## Context

Issue 216 (trial finding F-60): the user chooses which undercut and overcut bands the part shows. Decision 0163 agreed option C: a "Show" tick box on each histogram row and "Show only from … to … mm", per session, with the colour scale, the legend and the histogram following the choice, and the worst values and counts those of the whole part. The verification plan's row for SIM-15 asks that exactly the triangles in a hidden bin or outside the range keep the part's colour.

OI-627: a Simulate run with nothing changed took about 1.2 s on the owner's blisk project, about 1 s of it comparing the final stock with the part again (decision 0190, Consequences). The pipeline reused every path and every stock from the cache, then always called the comparison.

OI-840: `req_sim_03_the_skip_tick_box_is_the_projects_and_generating_follows_it` failed once on macOS CI (4.5 s), with "No cut part: …" not on screen, and passed when run again.

## Decision

1. **A bin keeps its identity across runs.** The histogram's bins lie between fixed edges (the colour thresholds 0.25, 0.5 and 1 mm, mirrored, and the surface band ±tolerance), so a bin is named by its place among them: nine places, four below the surface band, the surface band, four above it (`results_panel::bin_slot`, with the bins' own open and closed ends). A bin unticked stays unticked in the next run, the next setup and at another cell size; where the tolerance passes an edge, the places inside the surface band are empty. Each histogram row's tick box has the row's range as its label (the column is headed "Show  Range, mm"). A hidden row is drawn faint (30 %), a row the range cuts across half faint (60 %), each with a tooltip; the counts and shares stay. To fit the narrowest inspector with the tick box, the share is written without brackets ("998 99.8%") and the bar is 20 px at its longest.
2. **The comparison is kept with the stock it compares (OI-627).** A setup's simulation state keeps the comparison of its stock once a run has made it. The cache holds that state under the key of the operation that left it, and the key already fixes everything the comparison reads: the stock, the setup (its part's position, the held regions and tabs), the model and its file, and the cell (decision 0030 item 1). A run that ends a setup on a state from the cache therefore takes the comparison from it, and does not read the part's mesh either. Simulating on from a state clears the comparison, so a copy made to simulate on never carries one. A comparison made in a run is kept only after the run has checked that the part files did not change while it ran (`ModelFiles::parts_unchanged`, which refuses such a run), so one made from a changed file is never kept under a key made from the old one. `Regeneration::compared` lists the setups compared in a run, beside `simulated`. The report is the same either way (a test compares it with a run with the cache off, NFR-06). Memory: one comparison beside each cached stock that ended a setup in a run with a simulation, within decision 0190 item 3's one stock per operation.
3. **The range.** "Show only from … to … mm" takes signed millimetres (negative is overcut, as the histogram's ranges are), ends included; an empty field has no limit; a start above the end is refused with "The range starts above its end; swap the two values." and the range is left as it was. The range narrows the ticked bins. "Show all" ticks every bin and clears the range. The choice is kept by the results inspector for the session: a new run and another project keep it, and it is not saved.
4. **What is filtered, and how it is drawn.** The value filtered is the triangle's own value, the one it is coloured by and the probe reads (its worst sample). A triangle that was not measured has no deviation to filter and stays hatched, so it is never read as on the surface (NFR-12). A triangle not shown keeps the part's own colour. This now holds for "Colour by Remaining" and "Overcut" too: those left the triangles they hide out of the part's scene, so the part had holes where the cut stock showed through; the two choices combine with the filter.
5. **The views say so.** While anything is hidden, the results inspector says "Some bands are hidden." under the range, and the colour scale says "Some bands are hidden"; on the scale, a band wholly hidden is drawn at 25 % and a band partly hidden has its lower half at 25 %. No colour changes: the palette is lane SELSET's (issues 256 and 258). The worst values, the share within tolerance, the overcut count and the histogram's counts are worked out from the run, never from the filter.
6. **The test rig waits for playback (OI-840).** The cause is a race in the tests, not in the product. The note "No cut part: …" is one of the Playback tab's rows under the transport row, which the tab draws only once the playback panel has prepared the run for display, in a job that starts when the run lands. `Rig::settle` waited for the run, the scene and the checks but not for that job, so on a slow runner the test read the tab while it still showed only the transport row and "Preparing the toolpath for display…". Reproduced by delaying the job by 1.5 s: the test fails with the CI message. `Rig::settle` now also waits for the preparation (`PlaybackPanel::is_preparing`, for tests). With the delay in place the test, and the smoke tests that read the Playback tab's rows straight after a run (the same latent race), pass. No test is skipped or retried.

## Alternatives considered

- **Cache the comparison in the pipeline cache's entry, beside the stock:** rejected; it would have to be kept in step with the stock (dropped when the stock is, item 3 of decision 0190), while kept inside the state it goes with it.
- **Key the comparison separately (stock, part mesh, cell):** rejected for the reason decision 0190 gives for the stock: the operation's chained key already fixes all of them.
- **Name a bin by its ends:** rejected; the ends move with the extremes of each run, so a choice would not survive a new run.
- **A separate "Show" column of tick boxes:** about 27 px too wide for the narrowest inspector; the tick box labelled with the range costs 16 px.
- **Hide a filtered triangle from the scene, or draw it as on the surface:** rejected; the verification plan asks that it keep the part's colour, and the grey of the surface band would read as within tolerance.
- **Filter the not-measured triangles with the range:** rejected; they have no value, and hiding them would let a missing measurement pass unseen.
- **For OI-840, poll each assertion until it holds:** rejected; waiting for the state the assertion needs (the run prepared for display) is what the other Simulate tests already do, and it removes the race in every test that settles.

## Consequences

- `apps/openchuck-ui`: `results_panel` (`bin_slot`, `SLOTS`, `Bin::slot`, `BandFilter`, `Shown`, `SOME_HIDDEN`, the tick boxes, the range and "Show all"), `playback_panel` (`set_band_filter`, `shown_bands`), `viewport` (the part's triangles in no band shown keep the part's colour; `band_filter` for the scale), `viewport_overlays` (the scale's marks and note), `shell/inspector.rs` (hands the filter on), and the rig's `settle`.
- `crates/openchuck-app`: `SetupState::compare` and `finish`, `Regeneration::compared`; changelog entry. Not the library family, so no version bump (decision 0048).
- Interface specification 11.5: the band visibility bullet says what is filtered, how hidden bands are drawn and "Show all".
- Measurements: on the cube project the second Simulate with nothing changed compares nothing. The owner's blisk project is not in the repository, so the time saved there is the owner's run (OI-880); decision 0190 measured about 1 s of 1.2 s in the comparison.
- The "Colour the part by deviation" job still works out each triangle's value again for each new run (`start_deviation_bands`), even when the comparison was kept (OI-881).
- The part's grey (`#b7bfca`) and the surface band's grey (`#9aa0a8`) are close, so a hidden band can be hard to tell from "on the surface"; for lane SELSET's palette (OI-882). The notes in item 5 say when anything is hidden meanwhile.
