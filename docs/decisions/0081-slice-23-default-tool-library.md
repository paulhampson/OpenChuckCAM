# 0081: Slice 23 design refinement: the default tool library (lane TL)

- **Status:** proposed (17 Oct 2026). Owner-decided and relayed by the orchestrator (decision 0049) so far: the standard-tool list (OI-268), the route for the Makera data and the Z1 set (OI-269: the Z1 tool table, the shape mapping, material "carbide", the NXX numbering and its range up to 504, thread mills left out), as set out in item 8, and the update policy (OI-271, option A, explicit action). Still open: cutting data (OI-270). The owner has not yet accepted the record as a whole.
- **Date:** 17 Oct 2026.
- **Open items** are tracked in [docs/open-items.md](../open-items.md): OI-268 to OI-271 (from [decision 0060](0060-gc16-command-line-reading-and-tl12-default-tool-library.md)) are updated here.

## Context

[Decision 0060](0060-gc16-command-line-reading-and-tl12-default-tool-library.md) adds TL-12 (P1) and asks slice 23 to start with a record on the source and licence of the Makera data, the standard tools, cutting data, delivery and the update policy. Slice 4 ([decision 0014](0014-slice-4-tool-library.md)) built the library folder, tool sets and the sample corpus.

## Decision

1. **Source and licence of the Makera data (OI-269).** The owner named `MakeraInc/CarveraProfiles`. Read at commit `de08a657bdc9c230a094dbdba792acd70bfcdf32` (5 Aug 2026, shallow clone). It holds post-processors and tool files for many CAM programs (FreeCAD `.fctb` bit files, Fusion 360 `.tools` files, VCarve, Kiri:Moto and DeskProto files), a `Makera_Z1.fcm` machine file and Z1 design files. **It has no licence file** (no `LICENSE`, `COPYING` or `NOTICE`) and its README states no licence. The only licence text in it is on the post-processor code: Autodesk's copyright line on `Carvera.cps`, and sliptonic's LGPL-2.1 notice on the FreeCAD posts. **None of the tool data files carries a licence.** With no grant the data is under its owner's default copyright, so it is not clear that it may be embedded in an AGPL project (NFR-10). **Nothing was copied from the repository and no Makera value was re-keyed from it.** The owner then chose the route in item 8. Routes put to the owner: (a) ask Makera for a written grant; (b) write the Z1 tools from Makera's public product specifications with a recorded source per tool, citing the repository as a reference only (OI-269's own fallback); (c) re-key the facts by hand, which the lane will not do without the owner's say-so.
2. **Draft issue text for route (a), not sent.** "OpenChuckCAM is an AGPL-3.0 CAM program for 4-axis machining. We would like to ship the Makera Z1 tool list (types, dimensions and tool numbers) from `CarveraProfiles` as the default tool library. The repository has no licence file. Could you add one, or confirm in writing that the tool files may be copied and redistributed under the AGPL-3.0, with attribution if you wish?"
3. **Standard tools (OI-268), approved by the owner** (17 Oct 2026, in the orchestrator's session, relayed to lane TL by the orchestrator, decision 0049). The owner has 3.175 mm and 6 mm collets, which matches the shank sizes. 23 tools, all metric, defined for this project: nominal dimensions of a generic tool of each type, not taken from any vendor catalogue. Flat 1, 2, 3, 3.175, 4, 6 mm; ball 1, 2, 3, 3.175, 6 mm; bull-nose 3 mm r0.5 and 6 mm r1; tapered ball r0.25 on a 3.175 mm tool at 5 and 10 degree half angle; V-bit 30, 60 and 90 degree (6 mm, 0.1 mm tip); 90 degree chamfer (6 mm, 1 mm tip); drill 1, 2, 3 and 5 mm at 118 degrees. Shank equals diameter from 3 mm up, 3.175 mm below that; two flutes except the V-bits (one). The standard tools' own material is left unset: no source. The owner may adjust the list or the shank sizes later. The one list is `STANDARD` in `defaults.rs`, over files in `defaults/tools/`, so a change is a file edit and one line.
4. **Cutting data (OI-270), proposed; the owner has not decided.** None ships: no value is shipped, and invented speeds and feeds would break NFR-12. The tool files carry no `[cutting_data]`; a test checks it. The Makera bit pages give a reference table per bit (spindle speed, feed, plunge feed and depth of cut for up to eight materials, no stepover); it is not used, and the owner decides whether any of it ships.
5. **Delivery.** The files are in `crates/openchuck-project/defaults/tools/` (standard tools), `defaults/z1/` (Makera Z1 tools) and `defaults/tool-sets/` (the Z1 tool set), and embedded with `include_str!` (NFR-09, no network). `ToolLibrary::install_defaults` writes them into the user's library on first run in the existing file format (no schema change, no schema number claimed); `openchuck_app::library::install_default_tools_in_default_folder` runs it, and the UI calls it at start-up, reporting a failure without stopping. The command line does not install.
6. **Update policy (OI-271), owner-decided** (17 Oct 2026, relayed to lane TL by the orchestrator, decision 0049: option A, the explicit-action policy). A ledger file `.installed-defaults` in the library folder lists the IDs of the defaults installed. A listed ID is never installed again (a deleted tool stays deleted); an installed tool is never rewritten (an edited tool stays as edited); an ID the ledger does not know is installed (a later release adds a default); a default already in the library, for example by import, is recorded and not rewritten; a damaged ledger can only cause a missing default to be reinstalled, never an overwrite. **Chosen option (explicit action):** an installed default is never changed silently; an unedited tool is not replaced when a new version ships. The other option, silent update of an unedited default (needs a content hash in the ledger), was not chosen and is not built. A changed default reaches the user only through the explicit action `ToolLibrary::restore_defaults` ("Restore default tools"), which installs every default the library does not hold and never overwrites an existing file. Not built: a UI button for it, and delivery of a changed version of a tool that is still present (it would need a new ID or a copy beside it; to decide when a default first changes). The ledger does not end in `.toml`, so the library does not read it as a tool. A default tool set is ledgered by machine name and treated the same way: installed only when the library has no tool set for that machine and holds every tool it names, never overwritten, and not restored by a run.
7. **Room for further sets.** The embedded lists are `STANDARD`, `Z1` and `TOOL_SETS` in `defaults.rs`; another set of tools or another machine's tool set is added as files and one line, with no format change.
8. **The Makera Z1 tools and tool set (OI-269, OI-280, OI-281), owner-decided** (17 Oct 2026, relayed to lane TL by the orchestrator, decision 0049). Decided: (a) the route: use Makera's own tool pages primarily, and the community profiles at `Carvera-Community/Carvera_Community_Profiles` (read at commit `186e7b9`, **no licence file**; the owner knows) only for values the Makera pages do not state; facts only, no wording, images or file structures, each value sourced; **no claim of legal clearance is made**; (b) thread mills are left out and are a P2 item (OI-281); (c) the tool material is "carbide" for the Z1 bits, from the community profiles' material column, while the Makera pages say solid carbide, and TiN-coated solid carbide for the drills and corn bits (recorded so the coating is not lost); (d) the shape mapping: ball nose to ball, drills to drill with the 118 degree point, engraving to V-bit with included angle and tip diameter, chamfer to chamfer, O-flute and corn to flat end mill as the community files do; (e) the Z1 default tool set ships, with tool numbers in the form NXX, N a category (1 flat end, 2 ball, 3 V-bit, 4 chamfer, 5 drill) and XX counting from 01 in the table order; these numbers are assigned by this project, not read from Makera, the owner accepted the range up to 504 and may replace the numbers later; corn bits are in category 1 (106 to 109); (f) the table of 23 Z1 tools, approved ("go") and built as `defaults/z1/*.toml` and `defaults/tool-sets/makera-z1.toml`. The Z1 files carry no cutting data (OI-270 is undecided). Each file's header comment names its sources.

9. **The 4 mm and 6 mm shank extension (OI-269, OI-280, OI-281, OI-282, OI-283), owner-decided** (17 Oct 2026, relayed to lane TL by the orchestrator, decision 0049: go on the extension table, geometry only, material "carbide"). The owner also asked for the 4 mm and 6 mm shank parts on the Makera CNC bits page. 29 more Z1 tools are built, continuing each category's numbers so that 101 to 504 do not change: **flat end 110 to 121** (O-flute 4 mm: metal 4x12, 4x17, 4x22, then 4x22, 4x25, 4x32; 6 mm: metal 6x17, 6x25, 6x30, then 6x22, 6x25, 6x32), **ball 207 to 214** (metal 4x12, metal 6x18, then 4x12, 4x22, 4x32, 6x12, 6x22, 6x32), **V-bit 304 to 306 and 309 to 314** (4 mm shank: metal 30 deg tips 0.3, 0.4, 0.5, then 30 deg tips 0.3, 0.4, 0.5; 6 mm shank, two flutes: 20 deg tips 0.3, 0.4, 0.5). The Z1 set is now 52 tools; the tool set maps all 52. Sources are the same pages as in item 8 (`spiral-o-single-flute-bit-for-metal-4mm-shank`, `spiral-o-single-flute-bit-4mm-shank`, `spiral-o-single-flute-bit-for-metal-6mm-shank`, `spiral-o-single-flute-bit-6mm-shank`, `two-flute-ball-nose-bit-for-metal-4mm-shank`, `two-flute-ball-nose-bit-for-metal-6mm-shank`, `two-flute-ball-nose-bit-4mm-shank`, `two-flute-ball-nose-bit-6mm-shank`, `single-flute-engraving-bit-for-metal-4mm-shank`, `single-flute-engraving-bit-4mm-shank`, `two-flute-engraving-bit-6mm-shank`) and the same community files (`Makera O Flute Bits.csv`, `Makera Ball Endmills.csv`, `Makera Engraving Bits.csv`); each file's header says which. **The one inference:** where a page lists several sizes beside several total lengths (the non-metal 4 mm O-flute and the 6 mm O-flute, the 4 mm and 6 mm ball nose pages), the sizes are matched to the lengths by position; the community file agrees with every one. **Community-only values:** cutter diameter and flute length of the eleven engraving bits (4 mm engraving: diameter 4, flute length 7; 6 mm two-flute engraving: diameter 6, flute length 17). No disagreement on any number between the pages and the community file. **Held (OI-283):** the two 4 mm engraving bits with tips 0.1 (307) and 0.2 (308) are not built, because with the community-only diameter 4 and flute length 7 a 30 degree cone needs 7.28 and 7.09 mm to reach the diameter, which exceeds the flute length and fails the tool validation; no diameter is derived to make them fit. **Left out (OI-281, OI-282):** the 6 mm thread mills (thread mills, P2); the three 6 mm shank tapered-ball engraving bits (the page gives no top diameter and does not say whether the tip figure is a radius or a diameter); the 4 mm and 6 mm chamfers (neither source gives the cutter diameter, the flute length or the flute count); the UV solder-mask removal tool (not a 4 mm or 6 mm bit; spring-loaded; does not map to our types).

## Alternatives considered

- **Copying the Makera files now.** Rejected: no licence (item 1).
- **Marking defaults with a flag inside the tool file.** Would change the tool file format and need a schema number; a ledger beside the library does not.
- **Reinstalling a deleted default on update.** Rejected by TL-12.

## Verification

Tests named after the requirement IDs in `crates/openchuck-project/tests/default_tools.rs` and `crates/openchuck-app/tests/library.rs`: every default validates, has a unique ID and no cutting data; every type in TL-02 and TL-03 is present; each shape equals its closed-form silhouette at 301 radii within 1e-9 mm; a first run installs the 75 tools (23 standard, 52 Z1) and the Z1 tool set and a second installs nothing; the Z1 tool numbers are unique, in range 101 to 504 and match each tool's category (shanks 3.175, 4 or 6 mm); the Z1 tools are carbide with no cutting data; an edited default is kept; a deleted default is not restored; an edited or deleted tool set is not overwritten or restored by a run, and the explicit restore brings it back over nothing; a new default is installed; a damaged ledger overwrites nothing; restore reinstalls a deleted default and touches nothing present; installing needs no source tree or network.

## Consequences

- TL-12 is met for the standard tools and the Makera Z1 tools and tool set, except what is still open: cutting data (OI-270), thread mills as a P2 item (OI-281) and the Z1 tool numbers being ours (OI-280, the owner may replace them). Slice 23 stays open in the work breakdown for those.
- No dependency, no schema number, no change to `requirements.md` or `architecture.md`. `openchuck-project` gains a public API (`InstallReport`, `LEDGER_FILE`, `default_tools`, `standard_tools`, `z1_tools`, `default_tool_sets`, `ToolLibrary::install_defaults`, `ToolLibrary::restore_defaults`), a minor addition.
