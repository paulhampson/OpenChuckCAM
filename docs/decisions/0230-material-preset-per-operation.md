## Context

Trial finding F-41 (issue 197): when adding an operation, the user wants to pick the material preset of the chosen tool, the cutting data that tool has for a stock material (spindle speed, feed per tooth, plunge feed, default stepover and stepdown), and change it later in the operation inspector. The owner's answers on the issue: (1) the preset defaults to the setup's stock material and can be chosen per operation, with a warning triangle when the chosen material is not the setup's; (2) a tool with no cutting data for the material shows a clear message and applies no preset; (3) editing a value drops the preset, rather than marking it "Preset, modified".

On `main` (3335db8) an operation's unset cutting values follow its tool's cutting data for the setup's stock material: `parameter_values` fills the feed, plunge feed, stepover and stepdown, and `requirements::spindle_speed` the spindle speed (decision 0196). The material always came from the setup, so an operation could not use another of its tool's materials. Lane OPCREATE left the issue for after lane BUG-SPINDLE (decision 0204 item 6; OI-792), which is merged (pull request 267).

## Decision

1. **The operation may choose its preset's material (answer 1; project schema 18).** An operation gains the optional `material`, the stock material whose cutting data its preset takes. Empty, the preset is the setup's stock material, as before. One lookup, `preset::material_of`, serves every place that reads the cutting data: generation, the required values, the spindle speed, Post and export, the tool report's "no cutting data" warning and the setup sheet's "Speed from". A material is matched ignoring case and spacing (decision 0197) and is stored in the tool's spelling; choosing the setup's own material, under any spelling, stores nothing, so it follows the setup.
2. **Only the tool's presets are offered.** The list is the setup's stock material first ("Setup's stock material: Softwood"), then each other material the tool has cutting data for, in name order. The materials come from the project's copy of the tool (TL-07), which already holds its cutting data, so nothing more is snapshotted. A chosen material that is not the setup's shows a warning triangle with "\"Steel\" is not the setup's stock material, \"oak\"." (or that the setup has none). A material the tool has no data for cannot be chosen, and is refused in plain words if asked for (NFR-07).
3. **No cutting data for the material (answer 2).** The preset does not apply and the operation says why: "The tool \"6 mm flat\" has no cutting data for \"Softwood\", so no preset is applied. Choose another of its materials, or add cutting data for \"Softwood\" to the tool in the tool library." Without a stock material on the setup it says to choose one of the tool's materials or set the stock material. Choosing the setup's material then leaves the operation's own values as they are. The missing spindle speed and other required values are listed as before (decision 0196 item 3).
4. **Editing a cutting value drops the preset (answer 3; OI-980, the owner's option A).** Setting the spindle speed, feed, plunge feed, stepover or stepdown on the operation makes every cutting value the preset still gave the operation's own, as the preset gave it, in the same undoable step, so the toolpath and the G-code do not change. The operation then shows "No preset" in the Material preset box, and its tooltip says "No preset: a cutting value was changed on this operation. Choose a material to apply its preset again." (in the tooltip rather than as a line under the row, so an edit moves no row, UI-16). When the value edited is the spindle speed, the feed copied is worked out at the new speed, so the chip load stays the preset's (decision 0196 item 2). Clearing a value (↺) is not an edit and copies nothing; a parameter that is not a cutting value leaves the preset alone. Choosing a material again takes the operation's own cutting values away, so the preset fills them again.
   An operation shows a preset only while it sets none of the cutting values its strategy takes from the cutting data, so an older project with its own feed shows "No preset", which is what it has.
5. **New operation.** The dialog has a Material preset row under the tool, with the same list, warning and message. It starts at the setup's material, or at the selected operation's choice when the new operation takes its tool, and goes back to the setup's material when another tool lacks the choice. The operation is added with its preset in its one undoable step (`Application::add_operation_on` gains the material).
6. **The operation inspector.** The Tool section has a Material preset row under the tool number, above the spindle speed: the list, the warning triangle, and the message when no preset applies. The rows the preset fills keep their hint "from the tool's cutting data for Steel".
7. **The values are not written into the operation while the preset applies.** They follow the tool's cutting data as before, so an operation that chose nothing machines and posts byte for byte as before (GC-07): no golden file changes, and no migration of values.
8. **Project schema 18 (claimed in the work breakdown).** The operation file gains `material`, written only when chosen. Additive: the migration changes only the number, and refuses a schema 17 operation file that already holds the field. An empty material is refused when the project is checked. The library family is unchanged (`openchuck-project` and `openchuck-app` only).

## Specification entries proposed

For the owner to agree (OI-981); the specification is not edited by this record.

- **Section 11.4, New operation:** after the tool, "Material preset": the setup's stock material or another material the tool has cutting data for; a warning triangle when it is not the setup's; a note when the tool has no cutting data for it.
- **Section 11.4 (operation inspector), Tool section:** a Material preset row under the tool number, with the same list, the warning, and "No preset" once a cutting value has been changed on the operation.

## Not decided here

- Whether the preset meets TL-09 (P2, "a material library holding cutting data per material and tool, used to pre-fill the values in TL-05") in full. The preset pre-fills from the tools' own cutting data and the list of materials is derived from it (decision 0197 item 3); there is no separate material library file (OI-981).

## Alternatives considered

- **"Preset, modified" when a value is edited.** Not chosen by the owner (answer 3).
- **Writing the preset's values into the operation when it is chosen.** Every older project would need its values written in, or would read differently from a new one; following the tool's data keeps old and new the same and no G-code changes.
- **Dropping the preset in the display only (OI-980, option B).** The values not edited would keep following the material while the operation says it has no preset. Not chosen by the owner.
- **Offering every known material (decision 0197's list).** Materials the tool has no data for would apply nothing; the issue asks for the tool's presets only.
