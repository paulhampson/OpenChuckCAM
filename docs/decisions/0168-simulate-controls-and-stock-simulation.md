- **#204 (F-48).** Simulate's "Show: Stock, Part + path, Both" gave the same view for two choices, because the stock layer was empty until "Show the stock…" was pressed. - **#207 (F-51).** The A readout showed the continuous angle. Owner: the readout shows 0 to 360 degrees, and a tooltip gives the continuous value to compare with the G-code.

Asked through the coordinator: Output asks for an acknowledgement before writing while the stock simulation is skipped (OI-602, option C).
- **OI-697.** `PlaybackPanel::restore` showed an older run again after a turn-on by hand that followed another edit, although the tree marked it stale.

## Decision

1. **"Turn part with A" is on by default and remembered** (#203). It is `settings::SimulateSettings::turn_part_with_a` in the `[interface.simulate]` table of `settings.toml`, never in a project, so a project made before this change opens with it on. A settings file written before the field existed reads it as on (the table is additive). Untick it once and it stays off. The label is "Turn part with A".
2. **Simulate's view has three tick boxes** (#204): "Model" (the part's model), "Cut part" (the stock as the simulation cut it, at the play head) and "Toolpath". Any combination with at least one ticked. "Cut part" only is the default. The one ticked box is disabled, with the tooltip "At least one must stay ticked, so the view is never empty"; a stored choice with none ticked reads as "Cut part". They sit in the viewport toolbar on Simulate (7.1), and in the "Show" menu when the strip is too narrow (OI-529). They replace "Show: Stock, Part + path, Both". The dock's own "Toolpaths" and "Stock" tick boxes are removed: they did the same as these.
   - **The part coloured by deviation belongs to "Cut part".** The deviation colours are drawn on the model's surface (decision 0040). With "Model" unticked and the colours on, that coloured surface is still drawn while "Cut part" is ticked, because it shows what the cut left; with the colours off it is drawn only when "Model" is ticked. Without this the default view (Cut part only) would hide the colours and the probe of decision 0162. The owner chose this rule (OI-603, option A).
   - **Remembered between runs as a per-user setting** (`show_model`, `show_cut_part`, `show_toolpath`), the owner's answer to OI-600, as #203's answer does for the neighbouring control. A first start has Cut part only.
3. **The A readout is wrapped into 0 to 360 degrees** (#207), in the dock's readout line (three places) and in the viewport's readout box (two places), by `playback::wrapped_a_text`. Exactly 360 and a value that rounds to it read 0 (the lane's choice, as the issue allowed: the readout never shows both 0 and 360 for one position); a negative angle wraps; no value reads "-0.000"; a value that is not a number reads "-" (NFR-07). A tooltip on both gives the continuous value, "Continuous A in the G-code: 725.500°", by `playback::continuous_a_text`. Display only: the toolpath, the timeline's poses and the G-code keep the continuous angle (GC-07, NFR-12). Test `req_sim_02_the_a_readout_wraps_into_0_to_360_and_the_path_keeps_its_turns` checks the edge cases, that the G-code still holds A words past 360 and that it is unchanged.
4. **The stock simulation runs by default** (#214). `Application::start_generate` and `start_generate_until` simulate unless the project skips it: Generate stale, Generate selected (G) and the footer's primary all go through them. "Generate and simulate" in the menu always simulates, as it says. When a simulated run is in the playback panel, the Simulate step is open and "Cut part" is ticked, the cut part (the stock at the play head, decision 0040 item 5) is prepared without being asked for; no other step pays for it; the "Show the stock…" button is gone, and the Jobs tab calls that job "Simulating the cut part for playback".
5. **The skip is per project, with a per-user default** (#214). `project.toml` gains `skip_stock_simulation`, written only when true (schema 15, below). The tick box "Skip stock simulation" is in the playback tab, with or without a run, and is one undoable step (`Command::SetSkipStockSimulation`). The per-user default is `SimulateSettings::skip_stock_simulation`, set in the Settings dialog ("Skip the stock simulation in new projects"), and `Application::create_with` saves it into a new project from the start. While a project skips it:
   - generating makes only the toolpaths, and the toolpaths and G-code are byte for byte those of a simulated run (they never depended on the report; test `req_sim_03_generating_simulates_the_stock_unless_the_project_skips_it`);
   - Simulate's primary asks only for stale toolpaths and then continues; the step's health is "attention" with "Stock simulation is skipped for this project, so the cut has not been simulated" (`overview::STOCK_SIMULATION_SKIPPED`), so the skip is visible on the step bar (NFR-12);
   - the dock says "No cut part: the stock simulation is skipped for this project".
6. **Output, while the project skips the stock simulation, asks for an acknowledgement before writing** (OI-602, the owner's option C). The export checks give one warning, "Stock simulation is skipped for this project, so the cut has not been simulated. Untick "Skip stock simulation" in Simulate to check it." (`EXPORT_STOCK_SKIPPED`), in place of the per-operation "has not been simulated" lines, which would tell the user to run what they chose to skip (the lane's call, which the owner left to it). The safety band of the export dialog shows the same sentence with the tick box "I know the cut has not been simulated for this project" (`EXPORT_STOCK_SKIPPED_LABEL`), and "Write G-code" stays disabled until it is ticked, with the tooltip saying so. Like the export acknowledgement of GC-16 it is asked once for each project on each computer: after the first write it is kept in the user's `settings.toml` (`[export] stock_skipped_acknowledged`, by the project's canonical folder, `Acknowledgements::lookup_stock_skipped` and `acknowledge_stock_skipped`), never in the project, and it is apart from the export's own. Nothing in the G-code changes.
7. **A stage of the progress** (#214, with a seam for lane BUG-PROG, issue 201). The pipeline reports `pipeline::STAGE_GENERATE` ("regenerate", one step per operation, which includes each operation's material removal) and then `STAGE_SIMULATE` ("simulate the stock", one step per setup, the comparison with the part). One percentage across the stages is BUG-PROG's; this lane adds the stage and names it, and changes nothing in how the footer shows progress.
8. **OI-697: only a current run is shown again.** `export::run_is_current` says whether every operation a run holds is still in the project, on, and has the cache key it had when the run was made (the key the pipeline cache, the tree and the export check use, so a rename is not a change, decision 0172). `PlaybackPanel::restore` shows a dropped run again only when it is current, so an older run the tree marks stale is never drawn or played again; an undo back to the run's state still shows it (OI-692). Test `req_nfr_12_a_run_changed_since_is_not_shown_again`.
9. **Specification edits** (made in the same change, after the owner agreed):
   - 7.1, the toolbar table: replace the row "Show: Stock, Part + path, Both | Simulate | SIM-03, SIM-05" with "Show: Model, Cut part, Toolpath, tick boxes in any combination; Cut part only by default; the one ticked box is disabled with the reason, so the view is never empty; the part coloured by deviation shows with Cut part | Simulate | SIM-01, SIM-03, SIM-05".
   - 7.2, the readout: "A in degrees to 2 places, wrapped into 0 to 360 (360 reads 0); its tooltip gives the continuous A of the G-code".
   - 11.5, the playback dock: add "Skip stock simulation (the project's choice, undoable); the stock simulation otherwise runs with every generation and the cut part is prepared without being asked for" and "Turn part with A, on by default"; the readout line's A as in 7.2.
   - 11.6, checks before writing: "A project that skips the stock simulation gives one warning saying so, in place of the per-operation 'not simulated' warnings." And the safety notice band: "While the project skips the stock simulation, the band also says so, with the tick box 'I know the cut has not been simulated for this project', which must be ticked before writing; it is remembered as the export's is, per project on each computer."
   - 13, kept per user: add "the Simulate step's choices: Turn part with A, the view's tick boxes, Hide path outside window (decision 0169), and whether new projects skip the stock simulation (one tick box in Settings)".

## Project schema 15

`project.toml` gains `skip_stock_simulation` (this record) and `hidden_paths` (decision 0169), both written only when set. The work breakdown's claims table has the row. Schema 14 is lane BUG-SWARF's claim; on this branch a step that changes only the number passes through it, and that lane's step replaces it when its pull request merges first (claims rule 2). A schema 14 file that already holds one of the new fields is refused, naming the field. Neither field is an input to an operation's cache key: they live on the project, not on the operations, and `Project::same_output` compares two projects without them, which the export dialog uses so that hiding a path or ticking the skip does not post the files again.
