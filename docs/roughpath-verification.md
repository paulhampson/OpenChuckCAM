The historical owner project is **not on main**. It was recovered from `origin/claude/upbeat-davinci-jk46yd` at `c92fa236ccc8862e5a52e80eade69c73b835d7e0`, `docs/trial-feedback-projects/`. - **Fixed owner plunge diagnostic:** 84,855 segments; final safe retract retains A593275. Generation took 89.733 seconds. - **#291:** the old single-line 3-degree entry refuses at pass 1563 after 263.514 seconds: its 37.506 mm run starts with stock 0.078 mm above the rapid stop. To reproduce from recovered data, copy the historical project and its sibling STL into a temporary evidence directory, run `cargo run -p openchuck-cli -- resave <project-copy>`, and edit only that copy. Put `spindle_speed = 13000.0` on the root operation record solely for the posting diagnostic. In its `[parameters]`, select `entry = "ramp"`, `ramp_angle = 3.0`, and optionally `ramp_back_and_forth = true`. Run `cargo run -p openchuck-app --example roughpath_evidence -- <project-copy> <output-directory>`; the example reports final segments, playback samples and both posts. Preserve the source fixture and its recorded model hash.

The Z1 command is existing supported counter bookkeeping: firmware 1.1.2 (`b3a2e26`) removes whole turns from the **live A counter**, without physical rotation, XYZ reset or saved-work-offset write. It is not ordinary `G92 A0`. Both post and replay formerly reduced exactly ±360 incorrectly; firmware retains those values. The correction preserves them and adjusts following absolute commands. No in-cut reset is introduced. There was no new hardware trial, and this does not certify a long cut's accumulated float-counter precision.

Reference/grouping goldens intentionally change boundary A words, explicit links, reset placement and time comments. The independent golden audit checks cutting geometry and feeds; it no longer assumes that every Z1 file needs a reset when its final counter is within ±360. Helical IR goldens remove only the terminal return. Setup-sheet time/version artifacts follow the changed path and workspace version. The accepted boundary exception applies to legacy Facing; its planning and cut geometry remain unchanged.

## Shared-file inventory and contracts for FACING and FINSTEP

ROUGHPATH owns existing roughing/layers and goes first on overlapping shared changes. FACING owns new end/box-side planning, coverage extents, target planes, previews and facing completion. FINSTEP owns adaptive finishing. **The merge of this complete ROUGHPATH implementation PR into main is FACING's prerequisite.** Design preparation can proceed now; implementation consumes merged interfaces only, with no cherry-picks or unmerged prerequisites.

It cannot be replaced with selected surfaces, coverage extents or Warn-only samples. The current app supports STL and shanks no wider than the cutting profile; unsupported exact STEP/body certificates refuse the option. |
| Roughing/layers: path `assemble.rs`, `assemble/entry.rs`, new `assemble/ramp.rs` | No edits to roughing strategy/layer planning itself. Shared assembly retains accumulated A. Optional reversing entry uses clearance-height links instead of roughing's local low links, and checks every approach, leg, reversal and final fed connection before emitting. False/absent retains the existing branch. |
| Region/strategy: path `strategy.rs`, `params.rs` | `StrategyInput::entry_safety: Option<&EntrySafety>` and `EntryParameters::back_and_forth` are new public fields. Coverage, finished target surfaces and protection remain distinct. Held regions and tabs stay protected. No new clipping/raising API is introduced, and there is no success signal claiming an unreachable requested face is complete. FACING must expose incomplete coverage and refuse when its future planner cannot reach the requested surface. This lane adds no machine-readable completeness field to existing extension return types: FACING must assess actual resulting coverage or add an explicit completion result in its own accepted design, rather than infer completion from successful generation. Intentional stock outside an extent must not mask overcut or another operation's unfinished material; the deviation target is not changed here.

FINSTEP overlap is limited to shared `StrategyInput`, entry, assembly, connected cache/file planning and post contracts. It should merge this prerequisite first, then pass its own whole-target certificate or leave optional entry unsupported. Any later change to envelope proof, region/refusal propagation or completion reporting needs explicit sequencing with FACING/ROUGHPATH rather than reinterpretation of these contracts. Adaptive finishing algorithms are untouched. Future FACING target-plane/virtual-target geometry must provide a certificate for the actual whole finished target; the current app construction from the original STL cannot be silently reused after changing the target definition. Expanding the shared certificate beyond `MeshSurface` or changing refusal/completion interfaces is a subsequent coordinated change, not an implicit part of this lane's accepted design.

## Host migration and ramp limits

The workspace/library family moves from 0.20.0 to 0.21.0 for the public API breaks. Update struct literals for the new fields. Hosts not supporting reversing ramp pass `entry_safety: None` and leave `back_and_forth` false. To enable it, supply the complete inputs above, then connect canonical groups independently for every program/file. Provide `PostJob.a_range` and work-frame `safe_z`; treat `RotaryBoundary` as nonmoving metadata.

One cutting diameter is the accepted minimum **usable tool-centre travel** (3.175 mm for the reported tool). Full-envelope proof is also required. The engine verifies a deterministic one-diameter corridor along the existing entry direction; it does not claim an exhaustive geometric search. The approved insufficient-length refusal is:

> Back-and-forth ramp needs at least {minimum} mm of usable tool-centre travel; only {verified} mm could be verified. Choose another entry or change the entry geometry.

Each descending fixed-A leg respects the configured angle and uses plunge feed; the final leg reaches target depth, followed by a separately checked flat feed to the first cut if needed. Depth is distributed to avoid a final sub-resolution horizontal reversal. A separate half-unit regression demonstrated that exactly 0.001 mm could round to equal written Z endpoints; the planner reserves 0.0012 mm on Z and 0.0022 mm in the plane, including the supported float-word bound. Generation is bounded to 10,000 legs and a shared 100,000 clearance budget, with cancellation throughout. Continuous sweep certification grows the full body by a ball enclosing each subinterval's translation; this is not endpoint-only or Warn-only sampling.

Written output needs at least three XYZ/A decimal places. `RotaryPrecision::Float32` reserves a full ULP at canonical |A| + 721 degrees; hosts must keep the effective connected/controller offset within 720 degrees or recertify the contextual path. The app enforces that bound through the actual reset sequence and also refuses float WCS/MCS coordinate words whose ULP exceeds 0.0001 mm. These refusals do not change work zero or add resets inside a cut. Decimal precision hosts still reserve written rounding. Any host using single-precision linear words must enforce the same ULP ≤0.0001 mm limit on work and machine coordinates, or provide a new certificate; three decimal places alone do not establish that float bound.

Repeated entry passes can engage the full tool width as a slot. Neither the length threshold nor the clearance checks establish tool suitability, feeds or machining validation. The existing NFR-12 verification notice remains applicable. Reducing the ramp angle is not offered as a remedy for insufficient corridor length.
